# LIBER — 개인 홈페이지형 블로그

HTML, CSS, JavaScript만으로 실행하는 개인 블로그의 1차 버전입니다.

## 실행 방법

1. 압축파일을 해제합니다.
2. `index.html`을 Chrome 또는 Edge에서 엽니다.
3. 상단 **글쓰기**에서 포스팅하고, **설정**에서 디자인·서체를 조절합니다.

일부 브라우저의 로컬 파일 보안 정책 때문에 저장 기능이 제한된다면 폴더에서 터미널을 열어 다음 명령어로 로컬 서버를 실행하세요.

```bash
python -m http.server 8000
```

브라우저에서 `http://localhost:8000`으로 접속하면 됩니다.

## 구현된 기능

- 프롤로그, 게시글 목록, 검색·카테고리 필터, 글 읽기
- 서식 편집기: 제목, 굵게, 기울임꼴, 목록, 인용문, 링크 등
- 게시글 작성·수정·삭제 및 임시저장
- 사진/동영상 파일 첨부, 유튜브 링크 삽입 (첨부 미디어는 본문 아래 표시)
- 로마 클래식/로마 나이트/모던 테마, Noto Sans KR 기본 서체
- 개인 `.ttf`, `.otf`, `.woff`, `.woff2` 파일 등록
- 블로그 제목, 소개, 글자 크기 변경
- JSON 백업 및 복원, 모바일 반응형, 부드러운 화면 전환
- 한글 문장 어절 단위 줄바꿈 우선

## 데이터 저장 — 중요

이 버전은 **로컬 체험판**입니다. 게시글과 첨부 파일은 **현재 브라우저의 IndexedDB**에 저장됩니다. 브라우저 데이터를 삭제하거나 다른 기기에서 열면 글이 공유되지 않습니다. 예시 게시물 3개는 첫 실행에만 추가됩니다. 실사용 글은 메뉴의 **설정 → 백업 내려받기**로 정기 백업하세요. 큰 동영상 첨부는 브라우저 저장 공간에 제약을 받을 수 있습니다.

**인터넷에 공개하는 실제 블로그**로 운영하려면 Supabase 등에서 사용자 인증, 게시글 DB, 미디어 스토리지를 연결해야 합니다. 정적 호스팅에 이 버전을 그대로 올리더라도 방문자 사이에 게시물이 공유되지 않으며, 글쓰기 버튼이 관리자 전용으로 보호되지 않습니다. **공개 전 운영자 로그인/권한 제어가 반드시 필요합니다.**

## 주요 파일

- `index.html`: 웹사이트 진입점
- `styles.css`: 전체 디자인, 테마, 모바일 반응형, 서체, 애니메이션
- `app.js`: 화면, 글쓰기, 설정, 데이터 저장, 백업/복원
- `assets/fonts/`: 사용자가 가지고 있는 Noto Sans KR 서체를 직접 넣을 수 있는 폴더

## 서체 관련

**Noto Sans KR을 기본 서체로 설정**했으며 인터넷 연결 시 Google Fonts에서 가져옵니다. 업로드하신 `NotoSansKR-VariableFont_wght.ttf` 원본은 압축파일에 다시 넣지 않았습니다. 오프라인에서 같은 서체를 쓰려면 해당 파일을 본인이 직접 `assets/fonts/` 폴더에 넣어 주세요. 폰트 업로드 기능으로 별도 서체를 등록할 수도 있습니다. 웹에서 서체를 공개할 때는 해당 글꼴의 **웹 임베딩/재배포 라이선스**를 확인하세요.

## GitHub Pages 배포

이 저장소의 **Settings → Pages**에서 아래와 같이 설정하세요.

1. **Build and deployment → Source:** Deploy from a branch
2. **Branch:** main
3. **Folder:** /(root)
4. **Save** 클릭

완료 후 주소: https://freijyun.github.io/LIBER/

> ⚠️ 현재 GitHub Pages에서는 프롤로그와 예시 글을 공개할 수 있지만, 방문자들이 동일한 게시글 데이터베이스를 공유하지는 않습니다. 글을 실제 발행하려면 관리자 로그인 + 서버 DB 연결이 필요합니다. 이미지 파일은 별도 스토리지 사용을 권장합니다.


## 외부 이웃 블로그 · Blogroll

- 상단 **이웃** 메뉴(`#/neighbors`)에서 네이버 블로그, 티스토리, 브런치, 개인 블로그 등 외부 링크를 프로필 카드로 표시합니다.
- 프로필 사진 URL은 선택 사항입니다. 없거나 불러올 수 없으면 이름의 첫 글자가 표시됩니다.
- **이웃 등록·관리**에서 이름, 블로그 주소, 소개, 이미지 URL을 입력하고 추가·수정·삭제할 수 있습니다.
- 관리 화면에서 저장한 변경은 **현재 브라우저의 임시 편집본**이며 방문자들에게 자동 공개되지 않습니다.
- 공개하려면 **① 목록 JSON 복사** 후 **② GitHub 파일 편집**에서 `neighbors.json` 전체 내용을 교체하고 **Commit changes**를 누릅니다.
- GitHub Pages의 모든 방문자에게 공개 이웃 목록이 표시됩니다. 수정·삭제 버튼은 관리 화면을 열 때만 보입니다.
- 이 기능은 **단방향 외부 링크 모음**이며 상대방이 가입하거나 수락할 필요가 없습니다.
- 블로그 주소는 HTTP/HTTPS만 허용하고 링크는 새 탭에서 열립니다.
- 프로필 이미지는 외부 사이트 정책에 따라 표시되지 않을 수 있습니다.

이웃 목록 저장에는 Supabase 또는 Google Drive 연동이 필요하지 않습니다.


## 계층형 카테고리 및 태그 (2026-10)

- **카테고리** 메뉴(`#/categories`)에서 게시글용 / 이웃용 분류를 각각 관리합니다.
- 트리 구조: 최상위 → 하위 → 하위의 하위 등, 단계 제한 없이 분류를 추가할 수 있습니다.
- 카테고리 선택 후 **이름 변경**, **상위 카테고리 이동**, **위/아래 순서 변경**, **하위 추가**를 할 수 있습니다.
- 삭제는 하위 카테고리가 없는 항목에만 허용됩니다. 게시글은 상위 분류로 옮겨지고, 이웃의 해당 분류는 상위 분류로 대체됩니다.
- 상위 카테고리로 게시글을 조회하면 하위 분류의 글도 포함됩니다.
- 글쓰기에서 계층형 카테고리를 선택할 수 있고, 하위 카테고리를 즉석에서 만들 수 있습니다.
- 게시글에는 선택적 키워드 태그를 최대 8개 추가할 수 있습니다.
- 이웃은 네이버·티스토리 등의 **플랫폼**과 사용자 지정 **주제**를 별도로 분류합니다. 하나의 이웃에 여러 주제를 지정할 수 있습니다.
- 카테고리 저장은 우선 브라우저에서만 적용됩니다. 모든 방문자에게 공유하려면 관리 페이지에서 **JSON 복사 → GitHub `categories.json` 편집 → Commit changes**를 진행하세요.
- 이웃 주제 변경도 GitHub의 `neighbors.json`에 반영해야 방문자에게 공개됩니다.
- GitHub Pages는 정적 사이트입니다. 이 화면의 카테고리 관리·글쓰기 기능에는 관리자 인증이 없으며 실제 DB 동기화 기능도 없습니다. 글은 여전히 브라우저에만 저장됩니다.
- 게시글 JSON 백업에는 글의 카테고리 ID와 태그가 포함됩니다. 카테고리 구조 자체는 별도 `categories.json`으로 저장·백업해야 합니다.


## 블로그 카테고리 사이드바

- 게시글 목록(`#/posts`)에서 카테고리를 가로 버튼 대신 왼쪽 **계층형 사이드바**로 표시합니다.
- 네이버 블로그식 분류 탐색을 참고했습니다. 상위/하위는 들여쓰기로 표시되고, 화살표만 눌러 접거나 펼칠 수 있습니다.
- 카테고리 이름을 누르면 해당 분류의 글을 보여 줍니다. **상위 카테고리 선택 시 하위 글까지 포함**됩니다.
- `전체 보기`에는 모든 글 수가, 각 카테고리 옆에는 하위 글을 포함한 글 수가 표시됩니다.
- 현재 분류는 배경색과 왼쪽 강조선으로 구분합니다. 펼침 상태는 브라우저에 따로 저장됩니다.
- 모바일에서는 상단 카테고리 버튼으로 사이드바를 열어 탐색할 수 있습니다.
- 사이드바의 관리 링크는 기존 `#/categories` 관리 화면으로 이동합니다. 데이터 저장·공개 방식은 변경되지 않습니다.

### 카테고리 순서 변경

- 카테고리 관리에서 항목을 선택하고 **⇤ 맨 위로**, **↑ 위로**, **↓ 아래로**, **⇥ 맨 아래로**로 정렬합니다.
- 데스크톱에서는 분류 목록을 드래그해 **같은 상위 카테고리에 속하는 항목끼리** 순서를 바꿀 수 있습니다. 상위 카테고리를 옮겨도 하위 카테고리 전체가 함께 표시됩니다.
- 상위 분류 자체를 바꾸려면 기존의 **상위 카테고리** 선택란을 사용하세요.
- 정렬 변경은 로컬 초안으로 저장됩니다. 모든 방문자에게 적용하려면 관리 화면의 JSON을 GitHub `categories.json`에 게시해야 합니다.


## 본문 중간 사진 삽입

- 새 글 또는 글 수정 화면의 서식 도구에서 **▧ 사진 삽입**을 누릅니다. 사진은 현재 본문 커서가 있는 위치에 배치됩니다.
- 이미지 여러 장을 한꺼번에 선택할 수 있습니다. 파일당 30MB 이하 이미지만 본문에 삽입할 수 있습니다.
- 삽입된 사진을 선택하면 사진 설명(캡션), 크기(100% / 75% / 50%), 정렬(왼쪽 / 가운데 / 오른쪽)을 바꿀 수 있습니다.
- 사진은 편집기 안에서 드래그하여 다른 위치로 이동할 수 있습니다(일부 모바일·브라우저에서는 제약이 있을 수 있습니다). 앞 문단/다음 문단 이동 버튼도 지원합니다.
- 게시글을 저장하면 위치/크기/정렬/설명은 `body`의 안전한 이미지 참조 요소로 보존되며, **이미지 파일 Blob**은 기존 `attachments` 배열에 저장됩니다.
- 게시글 열람 시 기존 첨부파일에서 해당 이미지를 찾아 본문에 렌더링합니다. 본문에 사용된 사진은 하단 첨부 미디어 영역과 상단 커버에 중복 표시하지 않습니다. 목록 썸네일에는 첫 번째 이미지를 사용할 수 있습니다.
- JSON 게시글 백업은 기존과 동일하게 첨부파일을 포함하므로, 본문 사진도 함께 내보내고 복원할 수 있습니다.
- **중요:** 현재 블로그의 사진·게시글은 여전히 각 브라우저의 IndexedDB에만 저장됩니다. GitHub Pages만으로는 다른 기기 또는 방문자와 게시물이 동기화되지 않습니다. 공개 게시를 위해서는 관리자 인증과 DB/스토리지 연동이 따로 필요합니다.
